# Постоянный игровой поток: что уже оптимизировано

Контекст: пользователь хочет уменьшить задержку самой игры, без конкретного сбоя. Проверка после локальных54994e5 и3701f17, без запуска перехвата, изменения settings.ini или перезапуска обхода.

## Подтверждённый путь

- Текущая «ALT11 белый 6»: game_udp использует `--out-range=<n4`, один fake с repeats10. При непрерывно отслеживаемом соединении это максимум30 фейков на первые3 исходящих пакета, не10 на каждый пакет матча. Новый поток или истечение conntrack начинают счёт заново.
- В pinned bol-van v1.0.6 `desync.c:915-927` проверяет C-флаг cutoff до доступа к Lua. `948-985` автоматически устанавливает его, когда все функции вышли за верхнюю границу range. Для game_udp при n>=4 дополнительный Lua helper для cutoff не требуется. Перехват драйвером, conntrack и C-разбор пакета остаются.
- В `desync.c:1849-1851` UDP-протокол распознаётся до вызова цепочки Lua. Поэтому отключённая Lua не означает, что пакет целиком обходит движок. Ранний PASS в C нельзя вводить без проверки повторного выбора профиля при новом распознанном протоколе.
- Действующий kernel filter уже исключает пустые TCP ACK, а UDP443 добавляется ограниченным QUIC Initial raw-part. Профиль game_tcp с circular имеет другие диапазоны и не равен UDP: правило «только первые3» нельзя автоматически переносить на его детекторы.
- После двух последних правок исходящий IPv4 UDP и TCP в обе стороны к четырём уже исключённым сетям Take-Two проходят мимо движка. Valve/Steam relay остаются в обработке: их исключение ранее ломало игру.
- Пресет с более узкими игровыми портами уже есть в tools/lib.ps1 и меню. Новая такая же функция не требуется; автоматическое сужение общих динамических портов без проверки совместимости не обосновано.

## Вывод для следующей работы

Новая постоянная Lua-обёртка, уменьшение repeats или ещё один таймер не дают доказанного уменьшения задержки установившегося UDP-потока. Не внесены изменения стратегий или новых глобальных сетевых параметров. Для следующей оптимизации нужны данные о стоимости C/WinDivert на реальном игровом потоке; ICMP, время HTTPS и TCP connect не следует выдавать за UDP RTT игры. Разделение веб- и игрового обработчиков потребует отдельного дизайна управления несколькими процессами и проверки порядка пакетов, а не настройки несуществующих queue/thread CLI-флагов.
