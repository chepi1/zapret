# V2: ограничить оперативное состояние обучаемой автосмены

Основание: automate_host_record в неизменённом upstream lua/zapret-auto.lua хранит каждый hostkey в сильной глобальной autostate без удаления. Предел2000 в ring-store касается отдельных подсказок, не этого runtime-состояния. Пользователь поручил автономное улучшение стабильности v2; текущий игровой замер не доказывает проблему CPU обхода.

Решение: собственный opt-in Lua-модуль после zapret-auto, глобальный LRU до4096 записей для наших обучаемых circular-профилей. Game TCP/UDP и legacy/custom без флага остаются на штатном пути. Поиск O(1), без таймеров/файловой записи/обхода всей таблицы на каждом пакете. Vendored файлы и CHECKSUMS не менять.

Активное соединение удерживает собственную ссылку на выбранную запись. Выселение удаляет только индекс, не переключает стратегию этого соединения. Выселенная запись больше не обучает общую память; новый поток получает обычную актуальную запись и подсказки существующего ring-store. Смена hostkey после раскрытия SNI не закрепляется за старым IP. Ошибка собственного слоя один раз включает штатный fallback вместо повторного сбоя обработки.

- [x] RED: воспроизвести неограниченный индекс, вытеснение/активное соединение, namespaces, раскрытие hostname, единственный вызов custom hostkey и legacy/fallback.
- [x] GREEN: модуль, opt-in только для Learn, защита детекторов от старой выселенной записи.
- [x] Измерить Lua heap на синтетическом churn, не выдавать за снижение пинга/память winws процесса.
- [x] Lua/composition/fingerprint проверки на TEMP и независимое read-only ревью.

Проверки: новый hostcachetest с реальным Lua5.4 developer runtime; существующие watch/store/linkguard/luatest, профильные check/profiletest/lintstrat/drystrat и astlint по необходимости. Native Lua без перехвата можно выполнить отдельным elevated helper с --intercept=0; не запускать живую стратегию, не перезапускать обход/службу. Никакой публикации v2. Личные4 untracked заметки и диагностические dist/runtime не добавлять в Git.

## Итог проверок

- Начальный RED сохранил5000 записей без лимита; отдельный RED ревью воспроизвёл двойной вызов custom hostkey при ошибке кэша. GREEN исправляет оба случая; неверный callback сохраняет upstream-ошибку, не отключая исправный кэш.
- В Lua5.4 при50000 разных сайтов:6596.8→1440.8KiB,50000→4096 индексированных записей. В настоящем winws2/LuaJIT5.1:7001.1→1640.0KiB. Это синтетический Lua heap; не память всего процесса и не измерение пинга.
- Настоящие hostcachetest, luatest (включая dispatch старого/нового соединений), watchluatest — exit0. Native store unit/timer/file-I/O также exit0 при отдельном повторе после молчаливого сбоя запуска дочернего Cygwin-процесса. Проверки выполнялись в TEMP, с пустыми фильтрами.
- Полный финальный run-all -Offline:46 групп, exit0 (dist/v2-hostcache-final-all.log). Native-проверки кэша, circular, network-context и ring-store выполнены также отдельно с admin. Первый полный прогон выявил прежний граничный сбой длины команды; он разобран и исправлен отдельно в2026-11-04-v2-capture-budget.md.
- Независимое read-only ревью завершено без открытых замечаний. Несколько circular namespaces на одном track вне поддерживаемой генерируемой конфигурации: как automate_conn_record/ring_conn, она использует один circular на соединение. Кэш ограничивает только индекс обучаемых профилей; живые ссылки соединений освобождает штатный conntrack.

Работа сохраняется локально на codex/v2, без смены версии1.9 и без публикации.
