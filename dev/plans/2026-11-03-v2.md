# Zapret v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** повысить устойчивость обхода и уменьшить измеренную стоимость обработки, обеспечив проверяемый выбор стратегии и восстановление после сбоев.

**Architecture:** оставить официальный winws2/Lua и совместимое PowerShell-управление. Выделять из lib.ps1 небольшие компоненты с явными контрактами: снимок окружения, описание итоговой конфигурации, измерение/выбор, управление/восстановление. Сохранять существующие функции как совместимые оболочки до миграции вызывающего кода.

**Tech Stack:** Windows PowerShell 5.1, .NET Framework, официальный zapret2 v1.0.6 как стабильная база, Lua; существующие PowerShell/Python-тесты. Новые бинарные зависимости требуют отдельного обоснования.

**Spec:** `dev/research/2026-11-03-v2-review.md` — исследование, подтверждённые пробелы, требования и границы.

## Global Constraints

- База для сравнения — v1.9 / `23c14e6ae6f9c2fa5a776d37a98bdc09c5c80452`.
- PS5.1, BOM для PowerShell, сохранение принятой кодировки/окончаний строк; dev-файлы исключаются из пользовательского ZIP.
- Пользователь использует Wi-Fi. Кабель и изменение роутера/NIC не являются условием улучшения.
- Открытая игра запрещает фоновые перезапуски. Исследовательские тесты по умолчанию выполняются на временных копиях, без живого WinDivert-перехвата.
- Не менять стабильную версию/бинарники и не публиковать v2 до завершения этапов приёмки. Живые A/B-сеансы выполняются отдельным явно обозначенным этапом.
- Никаких обещаний уменьшения игрового пинга по результатам HTTPS-тестов; численные цели задаются после baseline.
- Не публиковать runtime, SSID, внешние IP, PAC-URL и секреты. Локальный сетевой ключ не требует внешнего geo-IP запроса.
- Сохранять настройки, пользовательские списки и происхождение заимствованного кода. Не объединять несовместимые условия участников circular.

## Review Focus

- Сеть/списки меняются во время измерения: результаты не применяются к новому состоянию (задача 1).
- Наблюдение невозможно из-за прав/тайм-аута: сохраняется Unknown, а не ложный Closed/Offline (задача 2).
- Две стратегии имеют одинаковое имя, но разные условия/байты: не разделяют один fingerprint и неподходящий круг (задача 3).
- Поздняя стратегия выигрывает только из-за временного улучшения Wi-Fi: контроль дрейфа выявляет недостоверное сравнение (задача 4).
- Позднее внедрение нового формата не должно потерять старые пользовательские данные: сначала shadow-режим и точная резервная копия (задачи 1–4).

## Alpha1: достоверная конфигурация и измерения

### Задача 1. Неизменяемый снимок всех входов

Файлы: создать `tools/netstate.ps1`, `tools/recipe.ps1`, `dev/tests/contexttest.ps1`; изменить `tools/lib.ps1`, `tools/test.ps1`, `dev/tests/run-all.ps1`.

Контракты:
- `Get-NetworkObservation` возвращает `ObservedUtc`, `Known`, локальные идентификаторы активных интерфейсов, маршруты/режимы IPv4/IPv6, состояние DNS/прокси/TUN. Сырые данные остаются локальными; состояние ошибки не равно пустой сети.
- `Get-RunSnapshot -Settings -StrategyIds -Targets -NetworkObservation` возвращает `SchemaVersion`, `ContextKey`, `ConfigHash`, `Generation`, manifest реально используемых файлов и нормализованные настройки. Включить содержимое списков/исключений, blobs, Lua, бинарников и выбранных профилей; порядок hostlist-правил сохраняется там, где влияет на смысл.
- `Test-RunSnapshot -Before -After` возвращает `Compatible` и коды причин; не меняет файлы/процессы.

- [ ] Написать регрессии: одинаковый ввод стабилен; новый публичный DHCP-IP сам по себе не меняет контекст; новая Wi-Fi-сеть/TUN/значимый маршрут меняет поколение; одинаковый ASN не объединяет разные контексты.
- [ ] Добавить проверки изменения только списка, blob, исключения и стратегии с прежним ID/названием; snapshot, собранный во время изменения файла, не принимается как целостный.
- [ ] Реализовать snapshot на согласованной копии входов. Ключ неизвестной сети не должен превращаться в один общий доверенный ключ для всех неизвестных сетей.
- [ ] Встроить shadow-снимки в отчёт теста; прежнее ранжирование пока сохраняется. При несовместимости запрещать запись/применение результата.
- [ ] Прогнать contexttest, historytest, retrytest, astlint/check. Ревью, отдельный коммит.

## Следующие этапы: отдельные планы перед реализацией

- **Alpha2:** общий mutex/владелец службы между папками; идентификация операций; Job Object/heartbeat для тестов; журнал транзакций с аварийным восстановлением; последняя рабочая конфигурация. Принудительно завершать только тестовые процессы на изолированном стенде.
- **Beta:** быстрый отсев семейств, pacing, финалисты в рабочем режиме; TTL/LRU контекстной памяти, ограниченная запись состояния; измеренное сужение перехвата и бюджет фейков. До/после сравнивать с v1.9 на одинаковых сценариях.
- **Экспериментальный канал:** QUIC-feedback и upstream UAF-fix. Сначала проверить API совместимость и возможность воспроизводимой сборки, затем отдельные протокольные/нагрузочные тесты. Не подменять официальный бинарник незаметно.
- **Stable2.0:** миграция1.9→2.0 и откат, длительный прогон, сон/пробуждение/сменаWi-Fi/TUN, опубликованные границы проверки; CI и проверка содержимого ZIP.

Реализован следующий срез контекста: tools/netstate.ps1 возвращает только локальный хеш профилей/маршрутов через шлюз/DNS/прокси; ошибка = Unknown. В тесте фиксируются настройки и NetworkBefore; смена контекста отменяет применение. Снимок исходных данных расширен списками/фейками и новым модулем. Изменяемый autohostlist и .bak исключены. Имена ring-файлов учитывают сетевой ключ и содержимое стратегий. 14 contexttest и весь offline dist/v2-context-final-all.log прошли (Lua пропущена локально).

Ограничение черновика: для безопасного старта через сохранённую ImagePath постоянная ring-память временно отключена во всех неконтролируемых запусках; custom-detectors и адаптация в RAM сохранены. До стабильной 2.0 нужен координатор, контролирующий сеть в течение жизни процесса и обновляющий service-start. Поэтому полноценное долговременное восстановление памяти по Wi-Fi пока не считается завершённым. Проверки смены сети выполнялись на fixtures, реальная сеть не переключалась.

Реализован срез Alpha2: общий Global named mutex для управления фиксированной службой/драйвером, ACL SYSTEM/Administrators/currentSID, поверх него прежний file lease папки. Вложенные вызовы реентерабельны, занятость не ждёт бесконечно; abandoned ownership принимается после освобождения ОС. coordinatortest: 10 сценариев настоящих тестовых процессов/разных runtime, включая hard kill владельца и отказ file lease. Это защита владения, а не готовое восстановление незавершённой файловой транзакции.

Временные exploration/final winws2 получают независимый Lua exit timer, рассчитанный по числу волн/тайм-ауту с запасом: минимум120с, не более30мин; слишком большой бюджет отклоняется заранее. Обычная служба таймер не получает. guardtest подтверждает настоящий движок в dry-run; истечение без трафика требует admin и локально пропущено. Основной тестовый процесс по-прежнему очищается finally; таймер ограничивает последствия hard kill родителя, но не обещает мгновенное завершение.

Проверки: dist/v2-coordinator-final-all.log exit0, дополнительный starttest/updatetest/smoke после разведения тестовых mutex имён прошёл; coordinatortest10 и finalchecktest16. Независимое ревью не нашло блокеров в mutex/timer. Тесты используют уникальные Local mutex, не реальные Global-координаторы. Живой обход, системные службы и настройки сети не менялись. Сетевой watchdog и возврат контекстной памяти на диск остаются следующей частью координатора.

Завершён сетевой watchdog и возвращена персистентная память с динамической привязкой. tools/netwatch.ps1 — единственный писатель по file lease папки, только локальные наблюдения каждые5с, без управления драйвером/сетевыми настройками. Два согласованных наблюдения сети и состава конфигурации публикуются атомарно. Служба получает стабильное имя state; Lua подставляет ключ актуальной сети. Запуск с сохранённой ImagePath не использует старый сетевой ключ. При установке службы код добавляет отдельное задание Startup/Logon под SYSTEM; при удалении снимает его. На живом ПК задание не регистрировалось, watcher не запускался.

Ruling: протокол3 — epoch, network SHA256, 24 hex composition prefix; запись до128байт. Lua принимает только свежий маркер <=20с и строго новее старта процесса, читает его не чаще1раза/с. Неизвестность/истечение/смена сети сбрасывает hints; исходы старых соединений не смешиваются. Изменение Lua/списков/фейков/настроек даёт composition mismatch у уже загруженного процесса и запрещает запись, пока его конфигурация не соответствует watchdog. Память остаётся в RAM при отказе, автоматического перезапуска обхода нет. Время обнаружения ограничено опросом/сроком heartbeat, не является мгновенным.

Ruling: watchdog использует machine-контекст маршрутов/DNS/NLM, независимо от HKCU SYSTEM. Прокси-настройки пользователя остаются частью контекста автоподбора; локальный HTTP-прокси сам по себе не меняет маршрут прямого трафика winws2. Включены on-link split-TUN маршруты; собственные DHCP host routes исключены, NCSI connectivity status не входит в идентичность. Наружу выводится только хеш. HTTPS-кэш теперь привязан к network key и сверяет сеть до/после проб.

Проверки: watchtest20 (протокол, atomic replace, задача с mock регистрации, duplicate child); watchtest.lua20 — реальные Lua-детекторы на виртуальных пакетах/файлах, A→B→A, expiry, старое соединение, смена состава. Для локальных Lua unit установлен lupa2.6 только в игнорируемый dist/lua-test-runtime (не зависимость пользовательской сборки). watchluatest запускает native empty-filter при admin; локально выполнялся dev Lua runtime. Обычный luatest и реальное истечение test guard локально пропущены без admin. Полный offline dist/v2-watch-final-all.log exit0, ревью без блокеров, diff-check чистый. Истинный end-to-end service boot и живая смена Wi-Fi ещё требуют отдельной приёмки.

Промежуточный read-only замер наблюдения сети: dist/v2-watch-readonly-cost.json; первые3снимка были Known и стабильны, холодный511мс/453мсCPU, тёплые47–51мс/16мсCPU; PS-host151–160МБ private bytes. Это стоимость снимка на этом ПК, не доказательство ускорения обхода и не полноценный long-run benchmark. Расход RAM наблюдателя остаётся целью последующей оптимизации.
