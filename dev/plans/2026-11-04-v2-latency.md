# V2 latency diagnostics plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans inline with TDD and one final independent read-only review.

**Goal:** показывать распределение диагностической задержки и не смешивать ICMP, TCP-порты и игровой UDP; убрать блокирующие TCP-пробы трекера.

**Architecture:** чистый ограниченный latency store хранит завершённые наблюдения раздельно по literal IP/protocol/TCP port. Трекер использует прежние малые бюджеты проб, managed async TCP с собственным timeout/cleanup и ICMP с явным владельцем Ping. Replay не выполняет активных сетевых проб. Новые модули подключает только track.ps1; алгоритм стратегий/история не меняются.

**Tech Stack:** PS5.1/BOM, штатный .NET Framework/C# через lazy Add-Type, TEMP fixtures и loopback без WinDivert.

**Spec:** пользователь поручил продолжать автономно после UDP capture/link guard. Следующий согласованный приоритет — качество измерений задержки. Base eb9d515, текущая ветка codex/v2.

## Global constraints / decisions

- Не перезапускать живой обход/наблюдатель, службы или задачи, не менять Wi-Fi/маршруты. Не выполнять живой tracker/матч. Личные untracked заметки и настоящий runtime сохранить.
- Статистика: максимум128 streams и120 завершённых попыток на stream, окно600с по Stopwatch. Success/Timeout/Error раздельно; Cancelled не превращается в неответ или нулевую задержку. Невалидные/nonfinite/отрицательные ms не принимаются.
- Ruling: P95 по nearest-rank только после20 успешных проб; median/min/max по ответившим, всплески >= median+50мс. Это эмпирическое распределение ответивших проб, не доверительный интервал и не процент потерь игры. Цена ошибки: при редких TCP-пробах P95 долго остаётся неизвестным; count/неответы/ошибки видны отдельно.
- Ruling: ICMP и каждый TCP-порт — отдельные streams. Для UDP показывается только ICMP; TCP fallback только для того же TCP endpoint. Ответ старше60с не выдаётся за свежий. Цена ошибки: когда сервер запрещает ICMP, пинг UDP остаётся неизвестным вместо подмены TCP-значением.
- ICMP: максимум12 одновременно, не чаще5с на IP, после3 подряд неуспехов пауза60с с повторной проверкой. TCP: максимум3 одновременно, не чаще20с на endpoint. Deadline1000мс; новые фоновые процессы и внешние зависимости не нужны.
- C# TCP operation фиксирует время при завершении managed connect, закрывает сокет/таймер при успехе, timeout, ошибке и отмене; UI polling не добавляется к RTT. Импорт модуля не компилирует тип и не открывает соединений.

## Review focus

- Один IP с TCP443/TCP8443/UDP не смешивает успехи/ошибки и не выдаёт TCP за UDP ping.
- Молчание ICMP, local Error, отмена и отсутствие наблюдений различаются; неизвестное не становится0.
- Окно/лимиты/LRU действительно ограничивают память; старое хорошее значение не скрывает свежие неответы.
- Completion/timeout/cancel races освобождают владельца один раз; основной цикл не Wait/Sleep на TCP.
- Replay/закрытие/исключение не оставляют проб и не запускают внешнюю сеть/ETW control.
