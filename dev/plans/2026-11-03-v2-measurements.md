# Repeatable measurements Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** обнаруживать воспроизводимое изменение контрольных запросов до/после автоподбора и сохранять исходные попытки для диагностики.

**Architecture:** чистые функции в tools/selection.ps1 задают seed-порядок, проверяют два контрольных пакета и сериализуют журнал. tools/test.ps1 делает одинаковые Clean-пробы без обхода в начале/конце, до записи истории проверяет качество данных. При нескольких раундах соседняя пара использует обратный порядок. Старое начисление баллов и конечный replay сохраняются.

**Tech Stack:** PowerShell5.1/.NET, UTF-8 BOM, штатный curl. Новых зависимостей нет.

**Spec:** dev/research/2026-11-03-v2-review.md P1, dev/plans/2026-11-03-v2.md Task4. Это ограниченный первый этап; полный A/B/B/A финалистов с интерполяцией времени и оценкой неопределённости остаётся отдельной задачей.

## Constraints and decisions

- Только fixtures/TEMP при работе агента; не запускать живой автоподбор, драйвер, службы или смену Wi-Fi/Happ.
- Релиз и официальные бинарники не менять, не публиковать v2. Настройки и прежний рейтинг сохраняются при отклонении измерений.
- Ruling: пользователь поручил продолжать v2 самостоятельно, поэтому выбираю существующие PS5.1/curl и самостоятельно ограничиваю накладные расходы. Не спрашивать повторно о реализации.
- Ruling: контроль — максимум5 уже имеющихся Clean-адресов, предпочтительно bing/github/pypi/aws/steam; fallback по объявленному порядку. Один прогрев и два измерения вначале, два в конце, ширина не больше4. Максимум25 дополнительных HEAD-запросов без запрашиваемого тела; Rounds по умолчанию остаётся1. Range не является жёстким ограничителем размера и для контроля не используется. Контроль относится к прямому HTTPS, не доказывает состояние Wi-Fi, игр или голосовой связи.
- Ruling: неизвестность не означает потерю сети. Нужны минимум3 адреса с двумя успешными запросами в обоих окнах. Устойчивая смена доступности (оба OK→оба FAIL, или обратно) отклоняет данные; согласованный latency shift минимум3 адресов в одну сторону с неперекрывающимися диапазонами >max(250мс,50% меньшей медианы) тоже отклоняет. Небольшой шум и единичная неустойчивая попытка сохраняются как неопределённость. Это консервативная проверка повторяемости, не статистический CI и не полный детектор дрейфа внутри теста.
- Ruling: seed меняет только порядок. Он записывается в отчёт/журнал, но не входит в совместимость истории средних. Политика/код входят в inputs hash. При Rounds>=2 порядок каждой пары раундов обратный; hopeless retry counters сбрасываются по раундам.
- Ruling: журнал JSONL сохраняет фактические попытки ДО Merge-Retry и не выдает ipSkip-копии за новые запросы. Только group/name, opaque TargetKey, тайминги/результат/байты и захваченные hashes; URL/прокси-секреты не сериализуются. До64МБ/файл, ошибка сохранения останавливает применение результата. Новые DNS/first-byte/total тайминги отсутствуют как null, а не вымышленные нули.

## Review Focus

- Контроль изменился при прежнем network key: history/rank/settings не публикуются, рабочий обход восстанавливается прежним finally.
- Повтор успешен после первого провала: обе исходные попытки сохранены, обычные полбалла остаются совместимы.
- Пробы контроля выполняются при отсутствии наших winws2; не принять результаты работающего тестового процесса за baseline.
- Парные порядки воспроизводятся, не меняют исходный список стратегий/приоритет при ничьей.
- Missing/DNS-unknown/NaN/Infinity/неполные времена не превращаются в хороший контроль или нулевую задержку; журнал не содержит URL.
