# V2: one pinned manifest for the bundled core

Execute inline with the existing autonomous authorization, TDD and one final read-only review. Existing codex/v2 checkout; production native files remain v1.0.6, with the running bypass preserved.

**Problem:** core version/archive digest are in CHECKSUMS and notices, native hashes are duplicated in lib.ps1, and the component notice has another hardcoded baseline. The v1.0.7 staging experiment initially refused integrity because only CHECKSUMS had been updated. A coherent test snapshot also needs to validate the captured native/Lua bytes against their trusted pins, closing the interval after the earlier integrity check.

**Design:** tools/upstream.txt is a small strict ASCII-key/value manifest under the protected tools directory: schema, tag, source commit, archive SHA256, and the eight fixed official runtime paths. tools/integrity.ps1 reads at most8KiB with simultaneous no-write/no-delete sharing, rejects duplicate/unknown/missing keys, invalid encodings, noncanonical paths/versions and malformed hashes. It returns the hashes, raw content hash and derived CHECKSUMS block. Existing Script:UpstreamHashes remains the compatibility alias. The zapret2 notice baseline is derived from the loaded tag. The human CHECKSUMS prefix is derived/verified by the builder; it never supplies runtime trust.

The manifest is loaded once with lib; before any native execution its current raw hash must still match. The generic loaded-package snapshot includes that data hash, so watcher/test code cannot claim a newly edited pin file as its loaded state. Get-RunSnapshot validates already-captured official binary/Lua/filter hashes while all source streams remain pinned. Get-ScoreInputFiles and the release allowlist include the new module/data. Normal play creates no snapshots, performs no network calls and does not write configuration.
