# V2 coherent inputs for strategy tests

> Execute inline with superpowers:executing-plans and TDD. User explicitly asked to continue autonomously. Existing codex/v2 checkout; no live strategy test, service restart, adapter change or publication.

**Goal:** every experimental engine in a run reads the same coherent code/profile/list/blob bytes; learning in one engine cannot modify the next engine's initial inputs or the working autohostlist.

**Finding:** Start-TestInstance currently composes directly from the live package. NoAuto disables circular only; settings.autolist still names the working lists/autohostlist.txt. Before/after hashes cannot prove which bytes a native process loaded in between.

**Architecture:** tools/recipe.ps1 captures all inputs with simultaneous read/no-write/no-delete handles, validates the catalog twice and loaded PowerShell source hashes, and materializes a private TEMP snapshot. Native source bin handles remain pinned for the run: experimental processes use the original executable/bin so WinDivert's driver service never points to a disposable copy. All Lua/profile/list/fake/filter inputs are read from the materialized copy. Each engine gets separate autohostlist and runtime outputs seeded from snapshot settings/rank/cover. Scoped composition redirects Root/Lists/StratDir/Runtime and caches, then restores the caller before any real start/stop/result publication. Snapshot file paths/handles are private registry state; caller-mutable metadata cannot redirect cleanup.

**Contracts:** Get-RunSnapshot -Settings -Targets -NetworkObservation [-RequireSavedSettings] returns SchemaVersion1, Generation, ConfigHash, ContextKey, NetworkKnown and FileCount; Get-RunSnapshotTargets/Get-RunSnapshotSettings return fresh copies. Test-RunSnapshot returns Compatible and Reasons; Unknown never shares a trusted context. Test-RunSnapshotCurrent compares coherent live input metadata before result publication. Invoke-RunSnapshotScope creates an engine view and runs composition/start there; original exe/bin stay unchanged. Close-RunSnapshot releases owned handles and removes only its checked TEMP root, after the owned engine is confirmed exited.

**Inputs:** shared Get-ScoreInputFiles inventory (existing hashed modules/Lua/lists/fake), all tools PS modules and bin/strategies/windivert files, targets/suite metadata, optional autohostlist/settings/rank/cover/tested-strategies/post body/fresh suite. Source file paths/reparse points validated.64MiB/2048-file limits bound a capture. Hashes use raw bytes, sorted relative paths, normalized scalar settings and ordered endpoint values. ContextKey also binds the local network key; unknown contexts get a unique generation nonce. No endpoints, SSID or absolute paths in the persisted snapshot summary.

**Constraints:** PS5.1/BOM, standard .NET only, no upstream/binary/strategy edits; keep data privacy, Valve/Steam and all existing ranking/replay controls. Freeze is confined to explicit strategy tests; no extra per-packet or normal-game work. This is not a live-engine last-good supervisor or a full upstream recipe model.
